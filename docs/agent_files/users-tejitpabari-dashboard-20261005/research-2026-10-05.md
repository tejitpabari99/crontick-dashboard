# Personal dashboard for crontick outputs: landscape research

Method: WebFetch of GitHub repos/APIs/docs on 2026-10-05. Items marked (unverified) come from background knowledge, not fetched this session.

## Requirements recap
Widgets of varied types (markdown, list, table, chart, KPI, iframe); inputs = local file paths (md/JSON written by cron), URLs, APIs; auto-refresh on file change; grid add/remove/rearrange/resize/fullscreen; uniform theme; easy custom widgets (AI-generatable); localhost only; OSS.

## Notes on top candidates

**Glance** (https://github.com/glanceapp/glance): lightest, nicest uniform look, YAML + hot reload, custom-api + html + iframe + extension. `safeHTML` lets a template render pre-rendered md/HTML. Gaps: no drag-drop/resize/fullscreen GUI; no file://; so each cron output needs an HTTP endpoint (e.g. crontick daemon or `python -m http.server`). AGPL (fine for local use).

**Homarr** (https://github.com/homarr-labs/homarr): only candidate with GUI drag-drop grid AND an AI-aware custom widget system (v2 definition: sources + queries + sandboxed JSX; "create from AI prompts", import/export JSON; https://homarr.dev/docs/management/custom-widgets/). Notebook md widget, iframe widget (https://homarr.dev/docs/widgets/iframe/). Gaps: sources HTTP-only (no local file), refresh semantics undocumented, homelab-integration oriented, heavier stack (Redis/tRPC), board/DB-stored config.

**Dashy** (https://github.com/Lissy93/dashy): MIT, mature; widgets include iframe, html-embed, api-response, data-feed, Custom List (local JSON in user-data), `updateInterval` (https://dashy.to/docs/widgets). Gaps: no real grid resize, no md widget found, link-centric UX, Vue widget authoring.

**Grafana**: strongest for charts/tables/KPIs with drag/resize/fullscreen, but Infinity cannot read local files (https://github.com/grafana/grafana-infinity-datasource/discussions/54) and md/summary is second-class; heavy.

**Observable Framework / Evidence / Streamlit**: great at "file in, rendered page out" with live reload, but code-defined layout; no end-user drag/resize/fullscreen widget grid.

## Gaps vs requirements (no off-the-shelf tool covers all)
1. Local file paths as widget inputs: none natively except Dashy (local JSON list). Everything else needs HTTP; Glance/Homarr/Grafana/Homepage can be bridged via a local file-serving endpoint.
2. Auto-refresh on file change: only Observable (watcher) natively; others poll.
3. GUI add/resize/fullscreen on a uniform widget grid: Homarr/Grafana/SelfDashboard; Glance/Homepage/Dashy weak.
4. Agent-authorable widgets: Glance (YAML+template), Homarr (JSON+JSX, AI authoring) best; Dashy/Homepage need framework-code changes.

## Ranked recommendation
1. **Use as-is (partial)**: Glance + tiny file-to-HTTP bridge (could be a crontick daemon route serving job output files). Cheapest; cron output as markdown via custom-api `safeHTML`. Accepts: no drag/resize/fullscreen GUI, config by YAML (agent-friendly). Runner-up: Homarr with custom widgets v2 pointed at the same bridge, if GUI grid matters more than file-watch.
2. **Fork/extend**: Homarr (Apache-2.0) adding a "local file" source type and file-watch push; or Dashy (MIT) extending Custom List. Cost: deep into a large TS monorepo / Vue app, tracking upstream. Not recommended unless drag-grid UI is must-have and custom build is rejected.
3. **Build custom (recommended given the requirements)**: small local app, ~1-2 KLOC.
   - Frontend: React + Vite + TS, react-grid-layout (or gridstack.js) for drag/resize; per-widget fullscreen via Fullscreen API/modal; CSS variables theme tokens for uniform look.
   - Backend: Node/Fastify or Hono (same ecosystem as crontick); `chokidar` file watcher + SSE/WebSocket to push file changes; layout persisted as JSON file (git-friendly, agent-editable).
   - Widget contract: one folder per widget type with a manifest (name, input schema via zod/JSON schema) and a single React component; renderers: markdown (react-markdown), JSON table/list/KPI, chart (Recharts/uPlot), iframe, weather. A SKILL/template doc lets Claude generate new widgets in one file.
   - Widget inputs: `{type, source:{file|url|command}, refresh}`; file sources resolved server-side with a path allowlist.
   - Could ship as a crontick companion (read job output dirs directly).

Verdict: nothing off-the-shelf meets the "local file + grid GUI + AI-writable widget" combo; Glance (quick win) or build custom (best fit) are the realistic paths.
