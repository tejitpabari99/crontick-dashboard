# Card schema reference

A card is a folder `<feed>/<id>/` with two UTF-8 JSON files: `card.json` (the view definition) and `data.json` (the content, holding a type-specific `data` object). An alert is a single file `<feed>/alerts/<id>.json`. The model is in [cards-and-feed](../concepts/cards-and-feed.md) and [card-types](../concepts/card-types.md); this page is the exact contract. Source of truth: the zod types in `src/contract/`; machine-readable form in `schemas/`.

## Machine-readable artifacts

- `schemas/card-def.json` (card.json), `schemas/data.json` (generic data.json), `schemas/data.<type>.json` (data.json for one type, with its payload), `schemas/<type>.json` (the bare payload) for `markdown`, `table`, `list`, `kpi`, `media`, and `schemas/alert.json`. Generated by `npm run gen:schemas`; print one with `crontick-dashboard templates <type> --schema [card|data|payload]`.
- `templates/<type>/{card.json,data.json}` and `templates/alert/alert.json`: valid examples; print with `crontick-dashboard templates <type>` (or `--file card|data` for one raw file).
- `$schema`: every example starts with `"$schema": "../../schemas/<file>"`, a path relative to the file (card folders sit two levels below the data dir: `<data>/feed/<id>/card.json`). Editors use it for completion. `new` and server start copy the packaged schemas into `<data>/schemas/` so the path resolves. `$schema` is optional and ignored by the validator.
- JSON Schema cannot express everything. Validator-only rules: id pattern details, RFC 3339 checks, cron validity, the data path rule, duplicate list item ids, link/src rules. Use `validate` as the authority.

## File rules

| Rule | Detail |
|------|--------|
| Encoding | Valid UTF-8 text; a leading BOM is tolerated |
| Size | `card.json` at most 64 KiB, `data.json` at most 1 MiB, alert file at most 16 KiB (`too-large` / `card-def-invalid` otherwise) |
| Top level | A JSON object (not array, scalar, or empty file) |
| Card id | The folder name; never read from file bodies. Matches `^[a-z0-9][a-z0-9._-]{0,63}$`, not ending in `.`, base name before the first `.` not a Windows reserved name (`con prn aux nul com1-9 lpt1-9`). `alerts` is reserved; names starting with `.` are ignored |
| Alert id | The file name stem of `feed/alerts/<id>.json`, same pattern. Alert ids are separate from card ids |
| Ignored files | Inside card folders and `feed/alerts/`, names starting with `.` or ending `.tmp` are ignored (atomic-write temps) |
| Unknown fields | Preserved everywhere, never stripped. Keys starting `x-` are reserved for agents; the contract will never use them. A stray `id` key is kept but ignored (validate warns) |

## `card.json`

| Field | Type | Required | Default | Rules |
|-------|------|----------|---------|-------|
| `$schema` | string | no | | Editor hint, see above |
| `type` | string | yes | | One of `markdown table list kpi media`; others are `unknown-type` |
| `title` | string | yes | | 1-200 chars |
| `data` | string | no | `"data.json"` | Data file name, see the data path rule below |
| `layout` | object | no | all defaults | `{ column?, order?, height? }` |
| `layout.column` | `"left"`, `"center"`, `"right"` | no | `"center"` | Which column the card sits in |
| `layout.order` | integer | no | `0` | Sort position within the column (ascending, then id) |
| `layout.height` | `"S"`, `"M"`, `"L"`, `"auto"` | no | `"auto"` | Fixed height (body scrolls) or content height up to the `L` height |
| `priority` | integer | no | `2` | 0-5; `data.json` `priority` overrides it. 0-1 renders as a collapsed chip |
| `notify` | boolean | no | `false` | OS notification on a new data version |
| `show` | object | no | always visible | `{ cron, for? }` |
| `show.cron` | string | yes in `show` | | Standard 5-field cron (no aliases, no seconds): the window start |
| `show.for` | duration | no | until end of that local day | Window length |
| `staleAfter` | duration | no | never | Card shows Broken (`stale`) once its data is older than this (no-data cards count from the `card.json` time) |

Durations: `^[1-9]\d*(m|h|d|w)$`, at most 3650d (e.g. `30m`, `12h`, `7d`, `2w`).

**Data path rule.** `data` is a plain file name inside the card folder: 1-200 characters, ending `.json`, with no `/` or `\`, no control characters, not starting with `.`, and not `card.json`. Subfolders are not allowed, and a symlink that resolves outside the folder is refused. A violation skips the folder (`data-path-invalid`, see [errors](errors.md#skipped-folders)).

**Removed fields.** `kind`, `size` and `retention` no longer exist and have no effect; the contract treats them as unknown extras (kept, ignored). Alerts are separate files rather than a card flavour, `layout.height` replaces `size`, and nothing is archived.

## `data.json`

| Field | Type | Required | Default | Rules |
|-------|------|----------|---------|-------|
| `$schema` | string | no | | Editor hint |
| `data` | object | yes unless `error` is non-empty | | Per-type payload, below |
| `updatedAt` | string | no | file modification time | RFC 3339 timestamp with offset or `Z` (naive local time rejected). A change marks new content: resets Done and re-notifies. Set it only when content truly changed; without it every rewrite counts as new |
| `priority` | integer | no | from `card.json` | 0-5; overrides the card.json priority (effective priority = `data.json`, else `card.json`, else 2) |
| `error` | string or null | no | `null` | Non-empty string declares an error card: shown Broken with this message, `data` not validated. Empty string is treated as null |

An absent `data.json` is not an error: the card shows "No data yet" (see [errors](errors.md#no-data-yet)).

Shared value formats:

- `link`: `http`, `https`, `mailto` or `ms-outlook` URL, at most 2048 chars, no whitespace or control chars.
- `due`: `YYYY-MM-DD` or RFC 3339 datetime with offset or `Z`.

## Alert file

`<feed>/alerts/<id>.json`, one small object. Alerts are shown as one-line rows and persist until ticked.

| Field | Type | Required | Default | Rules |
|-------|------|----------|---------|-------|
| `$schema` | string | no | | Editor hint |
| `title` | string | yes | | 1-200 chars |
| `text` | string | no | | 1-200 chars, one line (no line breaks) |
| `link` | link | no | | Clickable |
| `priority` | integer | no | `2` | 0-5; sorts the strip |
| `notify` | boolean | no | `false` | OS notification on a new or changed file; body is `text` if present, else `title` |
| `show` | object | no | always visible | Same as in `card.json` |
| `updatedAt` | string | no | file modification time | RFC 3339 |

## Per-type `data` payloads

These tables describe the `data` object inside `data.json`.

## `markdown`

| Field | Type | Rules |
|-------|------|-------|
| `text` | string | required, at most 100000 chars; GitHub-flavored markdown |

## `table`

| Field | Type | Rules |
|-------|------|-------|
| `columns` | array | required, 1-50 entries; each a string label or `{ label, key?, sort? }` with `sort` in `text`, `number`, `date` |
| `rows` | array | required; each `{ cells, link? }`; `cells.length` must equal `columns.length` |
| cell | scalar or object | string, number, boolean, null, or `{ text, link? }` |
| `defaultSort` | object | optional `{ column, dir }`; `column` a valid column index, `dir` `asc` or `desc` |
| `searchable` | boolean | default `true` |

## `list`

| Field | Type | Rules |
|-------|------|-------|
| `items` | array | required (may be empty) |
| `emptyText` | string | optional text for an empty list |
| item `text` | string | required |
| item `id` | string | optional, non-empty; unique within the card; required when `action` is set |
| item `subtitle` | string | optional |
| item `checked`, `checkedAt` | boolean, RFC 3339 | optional; `complete` write-back sets them |
| item `due` | date or datetime | optional (shown in the browser's time zone, see [troubleshooting](../troubleshooting.md)) |
| item `link` | link | optional |
| item `links` | array of `{ text, link }` | optional, at most 5 |
| item `action` | `"dismiss"`, `"complete"`, or `{ type }` | optional. `dismiss`: one-way tick kept in server state. `complete`: the server edits `checked`/`checkedAt` in `data.json` |

## `kpi`

Canonical form `data.items`: 1-12 metrics. A single-metric flat form (metric keys directly in `data`) is accepted and normalized to `items`; using both is invalid.

| Metric field | Type | Rules |
|--------------|------|-------|
| `value` | string or number | required |
| `label`, `unit` | string | optional |
| `state` | `ok`, `pending`, `fail`, `warn` | optional |
| `trend` | `{ delta: number, dir?: up/down/flat, good?: up/down }` | optional |
| `link` | link | optional |

## `media`

| Field | Type | Rules |
|-------|------|-------|
| `items` | array | required, 1-50 |
| item `src` | string | required: `http(s)` URL or `data:image/*` URI |
| item `alt`, `caption` | string | optional |
| item `link` | link | optional |
| `layout` | `grid` or `single` | optional |

## Completed and filter reference

The snapshot (see [http-api](http-api.md)) carries what the UI needs for the Completed section; the header filter (All / Alerts / Cards) is UI-only and the server always sends everything.

| Snapshot key | Contents |
|--------------|----------|
| `completed` | Ordered references to Completed rows (each names a card or an alert and its id), newest first by `doneAt` / `tickedAt`, then id. Done cards uncapped; ticked alerts only if ticked within 7 days, newest 50 |
| `cards[id].done`, `.doneAt` | A Done card stays in `cards` with `done: true` and the time it was marked; it is absent from `columns` and `now` |
| `completedAlertItems` | Ticked alerts by id: `{ id, title, text?, link?, priority, tickedAt }`. `tickedAt` is the modification time of the file in `feed/alerts/.done/` |

## Validation outcome

`validate` and the server run the same functions on the same reader. Results: ok (with warnings), no data (card.json valid, data absent), Broken (reason in [errors.md](errors.md#broken-reasons)), or skipped (reason in [errors.md](errors.md#skipped-folders)). A passing card may carry warnings: `updatedAt` more than 5 minutes in the future (clock skew), and a stray `id` key.
